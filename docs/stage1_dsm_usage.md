# Stage 1 DSM B/C migration

Implemented on `codex/stage1-dsm-prior`, based on `main@22134e1`.
The original dev-gszoom-v2 checkout is unchanged. No merge into main has been
performed. Runtime code has no dependency on the ArtiFixer directory.

## Default behavior

| Stage 1 input | Initialization | Surface loss |
|---|---|---|
| No DSM prior | Original SfM | inactive |
| `--dsm_prior PATH` | Source B/C mixed initializer | enabled (C) |
| `--dsm_prior PATH --no_dsm_surface` | Same mixed initializer | disabled (B) |

`--dsm_surface` explicitly enables the flag. `--dsm_init` remains accepted for
compatibility but is automatically enabled by a nonempty prior path. A missing
prior file is an error, even for B. `--lambda_dsm_surface 0` makes the effective
loss inactive; the resolved configuration records this rather than claiming C.

The source replace_budgeted initialization, nearest-SfM color, normal-aligned
short axis, tangent/normal scales, confidence inheritance and holdout are retained.
The surface formula is source C's weighted `log1p((r/sigma)^2)`, coefficient
0.05, sigma 0.5, warmup 500, hold 5000, decay until 21000, late factor 0.2.
There is no normal/relative training loss in this migration. The prior's normal
is still used for initialization and surface distance. Stage 2 has no added DSM
loss call and does not inherit the default Stage 1 surface constraint.

`stage1_config.json` records requested/effective switches, active prior point
count, data and optimization configuration. `stage1_events.json` records finite
checks and actual topology/reset events. `--init_max_points N` caps the total
initial population for a smoke; default 0 preserves source population selection.

## Prepare a prior

An existing source `dsm_prior.npz` plus its `registration.json` can be reused.
To regenerate it, provide all paths explicitly:

```bash
python scripts/build_dsm_prior.py \
  --scene JAX_068 --scene-dir "$DATASET" \
  --dsm "$DSM_TIF" --dsm-txt "$DSM_TXT" \
  --scene-loc "$SCENE_LOC" --output "$PRIOR_DIR" --skip-previews
```

The builder estimates the vertical shift from the input SfM overlap, records
source hashes/CRS provenance, and writes only to the output directory. It does
not use trained Gaussians or a hardcoded height offset. Source points3D.ply is
only generated by the original reader when missing. Mixed `input.ply` belongs
to the experiment output, never the source dataset.

The migrated B/C code expects the registered prior in the final training metric
frame. Datasets whose reader additionally applies R/T normalization are rejected
until an explicitly transformed prior is supplied through a supported path;
this version does not silently transform a height grid under an arbitrary
rotation. JAX_068 has no R/T and follows the source identity reader path.

## Coordinate gate

Source camera distance/nominal far plane alone does not determine registration:
large focal length and principal-point offset must be included in projection.
Use genuine matching COLMAP image observations, not feature indices from a
separate RPC crop reconstruction:

```bash
CUDA_VISIBLE_DEVICES="$GPU" python scripts/validate_dsm_coordinates.py \
  --source "$DATASET" --prior "$PRIOR_DIR/dsm_prior.npz" \
  --observations "$COLMAP_IMAGES" --resolution 4 \
  --output "$RUN_ROOT/coordinate_gate.json"
```

The validator checks point/feature identity, measured training-track residuals,
positive depth, DSM support in actual Camera images and coordinate roundtrip.
It binds the resulting report to hashes of the points, cameras and prior.
Unsupported/failed validation writes a rejected report and exits 2.

The current local JAX_068 still lacks verified 2D observations for its 69,027
SfM points. The 5,002-point ECEF RPC crop reconstruction is a different input.
Consequently the real JAX_068 A/B/C smoke has not been started. An existing
registered NPZ or historical successful run does not bypass this acceptance item.
`scripts/prepare_dsm_prior.py` remains the initial diagnostic entry, separate
from the builder and final registered-prior validator.

## A/B/C commands and smoke

```bash
python scripts/run_stage1_comparison.py \
  --source "$DATASET" --prior "$PRIOR_DIR/dsm_prior.npz" \
  --output "$RUN_ROOT" --coordinate-report "$RUN_ROOT/coordinate_gate.json" \
  --profile stage1_dsm --smoke --gpu "$GPU"
```

`--dry-run` exports commands even while the gate is blocked, without training.
Without `--smoke`, `stage1_dsm` uses main Stage 1 settings for 30k steps;
`source_bc_replay` uses historical 10k screening settings with initial opacity and MoGe
coefficients set to zero (the original opacity-reset cooldown behavior is retained). These are separately named protocols, not equivalent experiments.

Smoke: resolution 4, 200 steps, total initial limit 20,000, densification from
50 every 50, opacity reset at 100, pause/save/resume at 100, surface warmup 20,
MoGe off. The runner rejects missing actual topology/reset events, nonfinite
loss/gradients, missing active C priors or failed resumed rendering/evaluation.
Old tuples (main 15 fields; source DSM 17 fields) remain loadable. New checkpoints
keep optimizer, prior state/hash, coordinates, RNG, sample stack, opacity cooldown
and schedules. Their resume preserves the Stage 1 learning-rate schedule.
An explicitly supplied surface enable/disable flag or surface coefficient
overrides the checkpoint value; omitted switches preserve its saved experiment.

## Tests and synthetic end-to-end check

Install the supplementary dependencies with `pip install -r requirements-dsm.txt`
after setting up the base environment and CUDA extensions.

```bash
python -m pytest -q tests/test_stage1_coordinates.py tests/test_dsm_migration.py
python scripts/smoke_stage1_synthetic.py --output "$SYNTHETIC_RUN" --gpu "$GPU"
```

For numerical parity tests against the original module, set
`DSM_REFERENCE_ROOT` to the source Skyfall-GS directory. Without that external
reference, the two parity tests skip; the remaining tests are self-contained.

The synthetic check compares geometric covariance rather than redundant raw
quaternions for tangent-isotropic splats, and records both differences.
It uses known coordinates, trains C for four steps with
appearance enabled, saves/resumes at two, compares the result with uninterrupted
training, then renders/evaluates the resumed checkpoint. It verifies plumbing,
not JAX_068 alignment or reconstruction quality. Split and actual point removal
are also exercised in separate GPU tests. A flat DSM's zero-spread Fourier
feature normalization is guarded against division by zero.

## Evaluation

```bash
python scripts/evaluate_stage1.py --model "$MODEL" --source "$DATASET" \
  --prior "$PRIOR_DIR/dsm_prior.npz" --iteration 200
```

Use `--output DIR` to evaluate old models without writing into their directories,
and `--geometry-only` to skip RGB rendering. The evaluator reports center-raster
height errors, coverage and limited held-out RGB L1/PSNR, and exports predicted
DSM grids/config/coordinate metadata. The comparison runner additionally reports
A/B/C on their common finite grid. Reusing the prior as reference is labeled
`controlled_same_dsm`; spatial holdout does not make it independent ground truth.
